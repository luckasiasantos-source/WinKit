# Validação do M14 — Rede e sistema

**Versão testada:**   **Data:**   **Windows da VM:**

Hipóteses a confirmar: **H19** e **H20** (Wi-Fi, passo 2), **H21**, **H22**, **H23**, **H24**. Faça a receita num PC (ou VM) com Wi-Fi salvo, uma unidade de rede mapeada, `JAVA_HOME` definido e uma pasta extra no PATH.

| # | Passo | Esperado | Obtido | OK? |
|---|---|---|---|---|
| 1 | Studio → Wi-Fi → "Ler redes deste PC"; desligar "senha" numa rede | Redes listadas; a corporativa aparece desabilitada; aviso de senha legível | | |
| 2 | Instalar na VM com placa Wi-Fi USB passada para a VM | A rede conecta **antes** do primeiro login; a rede sem senha pede a senha ao conectar | | |
| 3 | Procurar a senha da fixture/da rede nos logs (`ProgramData\WinKit`, `WinKit\Logs` no pendrive) | Nunca aparece (R-53) | | |
| 4 | Recursos do Windows: marcar WSL, Sandbox (edição Pro), .NET 3.5 e Servidor OpenSSH | Na edição Home, Sandbox aparece desabilitado com "exige Pro ou superior" | | |
| 5 | Instalar com a **rede da VM desligada** na Fase 1 | WSL e Sandbox ligados antes do login; .NET 3.5 instalado **sem internet** pela ISO montada só para leitura (H21, H22); a ISO não fica montada depois | | |
| 6 | Religar a rede antes do login | OpenSSH Server instalado na Fase 2 (`Get-WindowsCapability -Online -Name OpenSSH.Server*`) | | |
| 7 | Desabilitar um driver na VM antes da Fase 2 (ou usar um dispositivo virtual desconhecido) | Resumo com a seção "Dispositivos sem driver" e os ids de hardware; com internet, drivers achados no Windows Update listados | | |
| 8 | DNS: Cloudflare + "Exigir DNS criptografado" + lista "Anúncios (básico)" | `Get-DnsClientServerAddress` mostra 1.1.1.1 nos adaptadores (H23); `Get-DnsClientDohServerAddress` com o modelo; `doubleclick.net` não abre; o resto do `hosts` intacto | | |
| 9 | `winkit dns bloqueios remover-do-pc` | O bloco some; o resto do `hosts` fica igual byte a byte | | |
| 10 | Unidade de rede `Z:` para uma pasta compartilhada do host | `Z:` aparece no primeiro login e o Windows pede a senha (H24) | | |
| 11 | Manutenção: "Toda semana" + Sensor de Armazenamento | `taskschd.msc` → `\WinKit\Manutencao\AtualizarApps` como o usuário; rodar à mão gera `ProgramData\WinKit\Manutencao\winget.log`; Sensor ligado em Configurações; `ScheduledDefrag` habilitada | | |
| 12 | Variáveis: `JAVA_HOME` (sistema) e uma pasta no PATH do usuário | Num terminal novo após o login, `echo %JAVA_HOME%` e `where` acham a pasta; o PATH do Windows continua completo | | |
| 13 | "Aplicar neste PC" num Windows que já tem `GOPATH` com outro valor | A prévia mostra os dois valores e o WinKit não troca; com "substituir" ligado, troca | | |
| 14 | Repetir tudo com o Studio em inglês e espanhol | Textos traduzidos nas páginas novas e no resumo | | |
